# Weighted Thermodynamic Perturbation (WTP) with QMHub + Q‑Chem

This package postprocesses per‑frame QM/MM inputs (`qmmm.inp_????`) generated by the **QMHub** stage and evaluates **Weighted Thermodynamic Perturbation (WTP)** using **Q‑Chem**. It runs **in parallel over frames** for each umbrella window and organizes results by **theory tag** (functional/basis). Per‑window results are then concatenated, and you can optionally combine across all windows for MBAR/PMF analysis.

---

## What you get

* **Per‑frame outputs** (per theory): `E_QM`, `E_ref`, `dE` (and optional `forces`) saved as compact NPZ.
* **Per‑window combine** (per theory): concatenated arrays + a frame index CSV.
* **All‑windows combine** (per theory, optional): one NPZ spanning the full dataset.

---

## Inputs & Outputs

**Inputs (per window)**

* `windows/<WIN>/qmhub/qmmm.inp_0000 … qmmm.inp_XXXX` — produced by the earlier QMHub postprocessing step.

**Outputs (per window, per theory tag `<TAG>`):**

* `windows/<WIN>/wtp/<TAG>/frames/wtp_frame_####.npz` — per‑frame results.
* `windows/<WIN>/wtp/<TAG>/wtp_window_combined.npz` — concatenated arrays.
* `windows/<WIN>/wtp/<TAG>/wtp_window_index.csv` — frame ↔ input map.

**Optional (across all windows, per theory):**

* `wtp_all/<TAG>/wtp_all_windows.npz` (and `forces_all_windows.npz` if saved).

---

## Define your theories (functional/basis)

Use a small CSV (recommended): `wtp/theories.csv`

```csv
tag,method,basis
b3lyp631gd,B3LYP,6-31+G(d)
wb97xd_def2tzvp,wB97X-D,def2-TZVP
pbeh3c,PBEh-3c,def2-mSVP
```

Alternatively, use an environment variable:

```bash
export WTP_THEORIES="b3lyp631gd:B3LYP/6-31+G(d),wb97xd_def2tzvp:wB97X-D/def2-TZVP"
```

Each row/entry defines a **theory tag** (`<TAG>`) and its `{method, basis}`. Outputs are written under `windows/<WIN>/wtp/<TAG>/`.

## Q‑Chem configuration (via environment)

You can tune Q‑Chem through environment variables (optional):

```bash
export QCHEM_MEM=4000       # MB total memory
export QCHEM_MAX_SCF=200
export QCHEM_SCF_CONV=8     # 10^-8
export QCHEM_DFT_GRID=SG-1
```

> The WTP scripts call Q‑Chem through QMHub with the chosen `{method, basis}` and these runtime knobs.

## Run on SLURM (all windows)

Submit the array job (42 windows shown as example `0-41`):

```bash
# Concurrently split node cores across theories (default)
sbatch wtp/wtp.slurm

# Or run theories sequentially per node (use all cores per theory):
CONCURRENT=0 sbatch wtp/wtp.slurm
```

**Parallelization**

* **Across frames**: one MPI rank per core; each rank processes every P‑th frame (stride).
* **Across theories**: when `CONCURRENT=1`, ranks are split among theories on the node.
* **Threading** is disabled for consistency:

  ```bash
  export OMP_NUM_THREADS=1
  export MKL_NUM_THREADS=1
  export OPENBLAS_NUM_THREADS=1
  export NUMEXPR_NUM_THREADS=1
  ```
* Add SLURM binding for stable performance: `--hint=nomultithread --cpu-bind=cores`.

## Scripts

### `wtp/wtp.slurm`

SLURM array script that:

1. Stages inputs to node‑local scratch (`$SLURM_TMPDIR`).
2. Discovers frames by globbing `qmmm.inp_????` (no hardcoded counts).
3. Reads theories from `theories.csv` or `WTP_THEORIES`.
4. Fans out per‑frame WTP over cores (and per theory if `CONCURRENT=1`).
5. Runs per‑window combine per theory and syncs results back to `windows/<WIN>/wtp/<TAG>/`.

### `wtp/wtp_energy.py`

Runs a single‑frame WTP evaluation using **QMHub → Q‑Chem** and writes a compact NPZ.

```bash
python wtp_energy.py \
  --inp windows/00/qmhub/qmmm.inp_0007 \
  --outdir windows/00/wtp/b3lyp631gd/frames \
  --method B3LYP --basis "6-31+G(d)" [--grad]
```

Saved fields (per frame):

* `E_QM`: target QM single‑point energy
* `E_ref`: reference energy used for Δ (set by your protocol; default 0.0)
* `dE`: `E_QM - E_ref`
* `forces` (optional): QM forces (if `--grad` is passed)
* `meta`: JSON with `{inp, engine, method, basis}`

### `wtp/wtp_combine.py`

Concatenates per‑frame NPZ files → one per‑window NPZ and a CSV index.

```bash
# Per‑window (per theory)
python wtp_combine.py \
  --frames-dir windows/00/wtp/b3lyp631gd/frames \
  --outdir windows/00/wtp/b3lyp631gd

# Optionally combine across all windows for this theory (run once)
python wtp_combine.py \
  --frames-dir windows/00/wtp/b3lyp631gd/frames \
  --outdir windows/00/wtp/b3lyp631gd \
  --all-windows
```

Outputs:

* `wtp_window_combined.npz` with arrays `frame_index`, `E_QM`, `E_ref`, `dE` (and `forces` if present)
* `wtp_window_index.csv` mapping `frame → qmmm.inp_####`
* When `--all-windows`: `wtp_all/<TAG>/wtp_all_windows.npz` (and `forces_all_windows.npz`)

### `wtp/mbar_pmf2.py`

Local, modified MBAR routines for PMF/reweighting.

* Use numerically stable `logsumexp` where applicable.
* Consume arrays from the combined NPZ files above.
* Document your deltas vs upstream PyMBAR in the header.

## Quick sanity checks

* **Frames present**: `ls windows/<WIN>/qmhub/qmmm.inp_???? | wc -l`
* **Per‑frame outputs**: `ls windows/<WIN>/wtp/<TAG>/frames | wc -l`
* **Peek one frame** (Python):

  ```python
  import numpy as np
  z = np.load('windows/00/wtp/b3lyp631gd/frames/wtp_frame_0007.npz', allow_pickle=True)
  print(z.files)  # ['E_QM','E_ref','dE','meta',('forces' if saved)]
  ```

## Performance tips

* Prefer **more ranks** with `cpus-per-task=1`; no OpenMP.
* Use **node‑local scratch** to reduce shared FS contention; `rsync` results back once.
* If I/O bound, reduce `--ntasks-per-node` or set `CONCURRENT=0` to serialize theories.

## Troubleshooting

* **No frames found**: check `windows/<WIN>/qmhub/` and filename pattern `qmmm.inp_????`.
* **Throughput low**: bind cores (`--cpu-bind=cores --hint=nomultithread`), use local scratch, or lower rank count.
* **Large outputs**: omit `--grad` unless forces are required; they increase file sizes.
* **Re‑runs**: per‑frame NPZ design allows re‑processing only missing frames per theory.
